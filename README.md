# GPT対戦オセロ — 各自のPCで動かす配布検証

ゲーム一式を取得した人のPCで盤面・ルール・対局状態を動かし、その人のChatGPTに白の手を考えてもらう実験です。別の生成AI API、APIキー、固定の相手AIは使いません。GPTが判断する盤面や着手はChatGPTに送られます。

配布リポジトリ： https://github.com/tianzhongshenshu382-a11y/gpt-reversi-local

## 受け取り側で使うファイル

GitHub の **Code → Download ZIP** で取得して展開します。Windows x64を今回の検証対象とします。ARM64用Node.js取得処理もありますが、ARM64実機は未検証です。

`setup.cmd` は公式Node.jsをこのフォルダー内に取得し、固定された依存パッケージをnpmから取得します。npmキャッシュもこのフォルダー内の `.runtime/npm-cache` を使います。管理者権限、システムのNode.jsインストール、PowerShell実行ポリシーの変更は不要です。インターネット接続は必要です。

## 方法A：今回のオセロと同じHTTP接続

1. 展開したフォルダーの `start-local.cmd` を起動します。初回は依存関係を準備するので少し待ちます。
2. 表示される **ChatGPT MCP URL** を、自分のChatGPTの「プラグイン → ＋ → カスタムMCPサーバーを追加」に登録します。認証は None。この機能が利用できるアカウント・環境が必要です。
3. 作成したPluginをインストールし、チャットでそのPluginを選んで「オセロを開いて」と送ります。
4. 表示された盤面を「アプリをタブで開く」で右側に表示し、黒をクリックします。白はこのチャットのGPTが選びます。

ゲームの処理は自分のPCで動きます。Cloudflareの一時トンネルは、ChatGPTからそのPCのゲームに到達する通信経路です。作者のPCには接続しません。公開されるのはこのオセロ用エンドポイントだけです。対局はメモリー上の一時データで、会計データなどをこの試作に入れないでください。

起動したウィンドウを閉じると終了します。次回起動時は一時URLが変わるため、ChatGPT側の接続先を更新する必要があります。これは配布可能性の検証方法であり、導入体験の完成形ではありません。

## 方法B：デスクトップ版のローカルPlugin

この方法はトンネルを使わず、ChatGPT/Codexの対応するデスクトップ環境からゲームを直接起動する候補です。

1. `setup.cmd` でランタイムと依存関係を取得します。
2. 対応するCodex CLIが使える環境で `install-plugin.cmd` を実行します。
3. デスクトップ版のローカルチャットで `GPT対戦オセロ 各自PC版` を選び、「オセロを開いて」と送ります。Pluginを認識しない場合は作業を保存してデスクトップ版を再起動します。

ローカルPluginのインストールと、stdio経由のツール・UIリソース取得は検証対象です。ただし、それだけでChatGPT内のUI表示やクリックによるGPT起動が実証されたとは扱いません。実機結果は別途記録します。ローカルPluginの一般公開には公式の対象条件があり、通常のWeb版への追加と同じではありません。

## GitHub URLをチャットに貼る場合

PCのファイル操作とコマンド実行ができるローカルWork/Codex環境なら、このREADMEを読み、取得・セットアップ・接続の準備を代行できる可能性があります。通常のWebチャットがURLだけで利用者PCへ自動インストールする機能は、このパッケージでは提供しません。

今回使ったWebチャットにはWindows PCの実行機能がありませんでした。これはその検証環境での結果です。対応するデスクトップ版や、利用条件を満たしてローカルコンピューターへのアクセスを許可したWorkは別途検証が必要です。仕様上の条件は公式の説明を参照してください： https://learn.chatgpt.com/docs/enterprise/cloud-local-access

試す依頼文：

> このリポジトリのオセロを私のPCにセットアップし、私のChatGPTの右側に表示して遊べるようにしてください。READMEを読み、利用できる機能を確認してから進めてください。

接続の追加やホスト側の確認が必要なら、そこで利用者の操作が残ります。ファイルを読むこと、Pluginのインストール、ホストUIに表示することを区別してください。

## 中身と流れ

| ファイル | 役割 |
|---|---|
| `plugins/gpt-reversi-local/board.html` | ChatGPT内に表示するUI |
| `engine.mjs` / `game.mjs` | オセロのルール・対局状態。GPTの思考は含まない |
| `server.mjs` / `stdio.mjs` | 同じゲーム機能をHTTPまたはローカルstdioで公開 |
| `bridge.mjs` / `handoff.mjs` | 黒の着手を保存してから、ChatGPTに白の手番を依頼 |
| `skills/play-reversi/SKILL.md` | GPTがゲームを扱う手順 |
| `mcp.json` / `plugin.json` | 各自PC向けPluginの接続設定 |
| `.agents/plugins/marketplace.json` | リポジトリからPluginを見つけるための一覧 |

黒クリック → ローカルのルール処理と盤面更新 → `ui/message` で現在のチャットへ依頼 → GPTが盤面を読み白を選択 → ローカルのルール処理で着手 → UI更新、という流れです。

## 開発・再検証

`plugins/gpt-reversi-local` で、用意したNode.jsを使って `node --test integration.test.mjs distribution.test.mjs` を実行します。テストの白着手は固定の試験入力であり、GPTが自動起動した証拠ではありません。

配布物に `.runtime/`、`.local/`、`node_modules/`、個人の接続URL、スクリーンショット、チャット履歴は含めません。

## 今回の検証記録（2026-10-24）

- 検証環境はWindows x64とChrome上のChatGPT Work。同じPCの日本語・空白を含む別フォルダーに、ソースだけのZIPを展開して初回セットアップを再現しました。実際の別PC・別アカウントの試験はまだです。
- Node.jsの公式配布物と固定依存関係の自動取得、起動、各自用の接続URL生成を確認しました。元の作者用接続URLやランタイムの流用はありません。
- 0.2.1版をZIPから起動し、五つのテスト（HTTP、stdio、宣言したPlugin起動コマンド、独立プロセスの状態分離、着手の手番依頼）に合格しました。Skillの公式形式検証も合格しています。
- 実際のChatGPT右側に表示し、黒D3のクリックだけでGPT白C5、ページ再読み込み後に盤面版2への復元、その後の黒D6のクリックだけでGPT白E3まで確認しました。カスタムアプリのCSP強制適用を有効にした状態です。
- 0.2.0で見つかった、ホストが古い盤面を再表示する問題を0.2.1で修正しました。初期表示では着手ボタンを無効にし、ローカルから最新の盤面を取得してから操作できるようにしています。
- ChatGPT側で「表示できませんでした」→「もう一度試す」が必要になる現象が残っています。ブラウザー側の通信エラーログもあり、この初回表示の問題の原因は未確定です。
- ローカルPluginは0.2.1のインストールとstdio通信まで確認しました。このトンネルを使わない方式でのChatGPT内UI表示と自動応答は未検証です。
- GitHubへの掲載と、GitHubのDownload ZIPからの実ダウンロードを確認しました。25ファイルの内容は、改行形式・末尾改行を除き配布元と一致しています。
- 初回導入の追加試験で、0.2.1の固定情報に、公開レジストリから取得できない `forwarded@0.2.1` が残っていたことが分かりました。それ以前の成功は利用者プロファイルのnpmキャッシュの影響を受けていました。
- 0.2.2では `forwarded@0.2.0` を指定し、インストール済みの部品を持たないフォルダーで固定情報を再生成しました。新しい空のキャッシュから97パッケージの取得に成功しています。以後は配布フォルダー専用のキャッシュを使います。
- GitHub URLと導入依頼をChrome上の既存のChatGPT Workチャットに送ったところ、クラウドのLinux環境への取得はできましたが、利用者のWindows PCへの展開・起動はできませんでした。したがって、そのWebチャットでのURLだけによるWindowsへの全自動導入は実現していません。
- GitHubから0.2.2をもう一度Download ZIPで取得し、新しい日本語フォルダーで、公式Node.jsと専用の空npmキャッシュから初回セットアップしました。全25ファイルの内容一致、97パッケージの取得、起動と新しい接続URLの生成、五つのテストの成功を確認しました。
- そのGitHub取得物を実際のChatGPTに新しいPluginとして接続し、右側に表示しました。黒D3のクリック後に追加の入力・送信をせず、GPTが白C5を選んで着手し、盤面版2・黒3白3になることを確認しました。前の試作Pluginへの接続を流用していません。
- Webチャット側でも0.2.2の新規取得と空キャッシュでの `npm ci` を再試験し、97パッケージ・終了コード0・forwarded 0.2.0の適用という結果を受け取りました。クラウドから利用者PCにアクセスできない制約は残ります。
